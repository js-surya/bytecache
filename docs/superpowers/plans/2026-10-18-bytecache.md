# ByteCache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ByteCache, an unofficial native ByteStash client for iPhone, iPad and Mac with share-sheet capture, browsing/editing, and on-device production-grade language detection — every feature on all three platforms.

**Architecture:** One local Swift package `ByteCacheKit` holds all logic and shared SwiftUI (modules `ByteCacheCore` → API/auth/cache, `ByteCacheLanguage` → detection, `ByteCacheFeatures` → view models + shared views) and is tested with `swift test`. A thin multiplatform app target (iOS + macOS, native — not Catalyst) plus one share extension per OS consume it. The Xcode project is generated by XcodeGen from `project.yml`; a separate tool package trains the Core ML language model.

**Tech Stack:** Swift 6.4, SwiftUI, Observation, SwiftData, AppIntents, NaturalLanguage + Core ML (model trained with Create ML), XcodeGen (installed at `/opt/homebrew/bin/xcodegen`), HighlightSwift (SPM) for highlighting.

**Spec:** `docs/superpowers/specs/2026-10-18-bytecache-design.md`

## Global Constraints

- Deployment targets: iOS / iPadOS 17.0, macOS 14.0. Build with Xcode 27.1.
- Full feature parity: a task's feature is not done until it builds and works on iPhone, iPad and Mac. Only allowed gap: multiple windows on iPhone (full-screen detail instead).
- Written from scratch against the HTTP API. Never copy code from the GPL-3.0 ByteStash repo; using its language id list as data is fine.
- Product copy calls it "ByteCache — an unofficial client for ByteStash". No ByteStash logo.
- No analytics, no data collection; never read the clipboard without a user action (system paste permission / `PasteButton`).
- No third-party networking. Only third-party dependency: HighlightSwift (must support iOS + macOS).
- Auth header: `bytestashauth: Bearer <jwt>`. All API paths are relative to the user's server base URL, which may include a sub-path.
- Snippet `PUT` replaces the whole snippet: always send title, description, categories, all fragments, and the current `is_public`.
- Language detection fully on-device. Language ids must be from `LanguageCatalog.ids` (ByteStash's ids).
- Test server: `https://bytestash-demo.pikapod.net`, `demo` / `demodemo`. Public — never put real code there.
- Bundle ids: `app.bytecache.ByteCache`, `app.bytecache.ByteCache.Share` (iOS), `app.bytecache.ByteCache.ShareMac` (macOS). App group: `group.app.bytecache` (iOS), `$(TeamIdentifierPrefix)app.bytecache` (macOS), passed to code via Info.plist key `BCAppGroupID`. Keychain access group: `$(AppIdentifierPrefix)app.bytecache.shared`, Info.plist key `BCKeychainGroup`.

## Review Focus

1. **Server URL typed loosely** (`demo.example.com`, trailing `/`, sub-path `/bytestash`, pasted URL ending `/api` or `/login`) — must normalize to the right base, never double slashes. Pinned in Task 2 tests.
2. **Token expires mid-use (24h default) or is revoked** — any 401 from any call, including inside the share extension, signs out cleanly and shows login; the share extension keeps the user's unsaved code and tells them to open ByteCache. Pinned in Task 4, Task 13 and Task 14 tests.
3. **Editing a public snippet** — save must not silently make it private or drop fragments/categories. Pinned in Task 2 (draft from snippet) and Task 11 tests.
4. **Huge or odd captures** — 5,000-line paste, empty selection, a shared URL with no text, CRLF / tabs / non-UTF8-looking text. Detection must stay fast (input capped to first 400 lines for the classifier), empty text must disable Save. Pinned in Task 7, Task 8, Task 12 and Task 13 tests.
5. **No network** — list shows cached snippets with an "Offline" label instead of an error screen; writes show a retryable error and keep the user's edits. Pinned in Task 5 and Task 10 tests.

### Task 8: Detector pipeline, disambiguation, acceptance eval
